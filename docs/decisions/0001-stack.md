# 0001. Стек мобильного приложения

Дата: 2026-10-12 · Статус: принято

## Контекст

Нужно приложение для iOS и Android одной небольшой командой. Важны дизайн, скорость разработки, строгая типизация (команда пришла из Java) и работа вместе с Claude Code. Разработка идёт на Mac, есть iPhone для тестов.

## Решение

- **React Native + Expo** (managed workflow, development build, EAS Build/Submit).
- **TypeScript** в строгом режиме (`strict`, `noUncheckedIndexedAccess`).
- **Expo Router** — навигация на файлах.
- **expo-sqlite + Drizzle ORM** — локальная база, миграции, live-запросы.
- **Zustand** — небольшое UI-состояние; данные читаем из базы через хуки.
- **react-hook-form + zod** — формы и валидация (zod же валидирует результат парсера и ИИ).
- **FlashList** — длинные списки.
- **i18next + expo-localization** — ru / de / en.
- **Свой дизайн**: токены + компоненты в `src/ui`, шрифт Onest (expo-font), иконки lucide-react-native.
- **Jest + React Native Testing Library**; e2e позже (Maestro).
- **Позже (0.3+):** Supabase или Firebase (отдельное решение 0002), RevenueCat, Sentry, PostHog.

## Альтернативы

- **Flutter.** Сильная производительность и единый вид на обеих платформах, но Dart, Material по умолчанию и меньше «родных» системных мелочей на iOS. Для команды с TypeScript и упором на iOS-ощущение — проигрывает.
- **Нативно (Swift + Kotlin).** Лучшее качество платформы, но две кодовые базы — слишком дорого для MVP.

## Последствия

- Expo Go подходит до появления нативных модулей; с «Поделиться», покупками и рекламой нужен development build.
- Вид приложения задаёт наша дизайн-система, а не платформа: все экраны собираются только из `src/ui`.
