# 0002. Разбор вакансии на устройстве без DOM

Дата: 2026-10-12 · Статус: принято

## Контекст

В 0.1 ссылка разбирается прямо на телефоне (PRD 4.3). В React Native нет DOM-парсера, а класс `URL` неполный: не приводит хост к нижнему регистру, не проверяет адрес и по-разному ведёт себя на платформах.

## Решение

- HTML не превращаем в DOM. Регулярными выражениями достаём только нужное: блоки `application/ld+json`, мета-теги, `<title>`, видимый текст. Скрипты страницы никогда не выполняются.
- Свой разбор http(s)-адресов в `src/lib/url.ts`: всё, что не http/https, отбрасывается до загрузки; канонизация убирает `utm_*`, `gclid`, `fbclid` и похожие параметры, якорь, порт по умолчанию и сортирует оставшиеся параметры.
- Источники в порядке приоритета: JSON-LD → мета-теги → эвристики. Зарплата берётся из одного источника целиком, чтобы не смешать диапазон из одного места с валютой из другого.
- Результат каждого поля проверяется `zod`; невалидное значение отбрасывается, а не роняет весь разбор.

## Последствия

- Парсер — чистые функции, тесты гоняются в Node на фикстурах (`src/parser/__fixtures__`).
- Страницы, которые собираются скриптами в браузере (часть LinkedIn, Workday), на устройстве не разберутся: для них есть «вставить текст» и ручная форма, а в 0.3 — серверный `/ingest`.
- Реальные HTML по задаче #1 ещё нужно собрать и добавить в фикстуры; сейчас там синтетические страницы по известной разметке площадок.
