# CLAUDE.md — JobTracker

Мобильный трекер откликов на вакансии (iOS + Android): гибкая таблица, которая заполняется сама из ссылки на вакансию. Рынок DACH, интерфейс ru / de / en. Подробности — `docs/PRD.md`.

## Где что лежит

- **Задачи:** GitHub Issues + GitHub Project. Это источник правды. `backlog/BACKLOG.md` — только исходный импорт, его не обновляем.
- **Что строим:** `docs/PRD.md` (функции, модель данных, этапы, требования).
- **Почему так:** `docs/decisions/` — по файлу на решение (`0001-stack.md` и дальше).
- **Дизайн:** `docs/design.md` (токены) и холст с макетами в Claude (ссылку держит владелец проекта).

## Стек

React Native + Expo, TypeScript (strict), Expo Router, expo-sqlite + Drizzle ORM, Zustand, react-hook-form + zod, FlashList, i18next, lucide-react-native, Jest + React Native Testing Library. Обоснование — `docs/decisions/0001-stack.md`.

## Команды

```bash
npm install
npx expo start            # dev-сервер; iPhone через Expo Go или dev build
npm run typecheck
npm run lint
npm test
npm run check             # typecheck + lint + test — запускать перед каждым PR
npx drizzle-kit generate  # миграция после изменения схемы
```

## Структура

```
app/                      # экраны (Expo Router)
  (tabs)/index.tsx        # Отклики
  (tabs)/table.tsx        # Таблица
  (tabs)/settings.tsx     # Настройки
  application/[id].tsx    # Карточка
  add.tsx                 # Новая вакансия
src/
  ui/                     # токены, тема, базовые компоненты — единственный источник стилей
  db/                     # схема Drizzle, клиент, миграции, сид
  features/<feature>/     # хуки, компоненты и логика фичи (applications, table, import, reminders…)
  parser/                 # загрузка страницы и разбор вакансии; __fixtures__/ — реальные HTML
  i18n/                   # ru.json, de.json, en.json
  lib/                    # общие утилиты (format, url, crypto)
docs/
backlog/
scripts/
```

## Правила кода

- TypeScript strict, без `any` и `@ts-ignore`. Внешние данные (страницы, файлы, ответы сервера и ИИ) сначала через `zod`.
- Экраны собираются **только** из `src/ui`. Никаких цветов, размеров, шрифтов мимо токенов. Нет нужного компонента — добавь его в `src/ui` и на витрину `/dev/ui`.
- Все строки интерфейса через `t()`; новые ключи сразу в `ru`, `de`, `en`. Даты и деньги через хелперы `src/lib/format.ts`.
- Экраны не ходят в базу напрямую — только через хуки и репозитории фичи.
- Доступность: зоны нажатия ≥ 44 pt, `accessibilityLabel` у иконок, текст масштабируется.
- Обе темы проверяются для каждого нового экрана.
- Код, идентификаторы, комментарии и коммиты — на английском. Документация — на русском.
- Новая зависимость — только если без неё никак; упомянуть в описании PR, почему.

## Безопасность

- Любая страница вакансии, файл импорта и письмо — **недоверенные данные**. Лимиты размера и времени, никакого выполнения JS, храним чистый текст.
- Никаких ключей API в приложении. ИИ вызывается только через наш сервер (с версии 0.3).
- Текст из внешних источников в промптах — внутри тегов и как данные; ответ модели только по JSON-схеме и через `zod`.
- Экспорт CSV экранирует формулы (`=`, `+`, `-`, `@`).
- Серверный загрузчик ссылок защищён от SSRF (см. PRD, раздел 7).

## Как работать с задачей

1. `gh issue view <N>` — прочитать задачу, критерии готовности и зависимости. Если зависимость не закрыта — сказать об этом и остановиться.
2. Ветка `feat/<N>-short-name` (или `fix/`, `chore/`).
3. Сначала короткий план в ответе, потом реализация небольшими коммитами (Conventional Commits: `feat: …`, `fix: …`).
4. Тесты на логику (парсер, слой данных, утилиты) — обязательно; на UI — где есть поведение.
5. `npm run check` зелёный.
6. `gh pr create` с «Closes #<N>», списком сделанного и отмеченными критериями готовности. Для UI — скриншоты обеих тем.
7. Нашёл новую работу или баг вне задачи — `gh issue create` с метками (`type:*`, `area:*`, `P*`, `size:*`) и нужной вехой, а не раздувать текущий PR.
8. Принял архитектурное решение — добавь файл в `docs/decisions/`. Поменялась функция или модель данных — обнови `docs/PRD.md` в том же PR.

## Готово, когда

- Все критерии из issue выполнены и отмечены в PR.
- `npm run check` зелёный, CI зелёный.
- Нет строк мимо i18n, нет стилей мимо токенов.
- Экран проверен на iPhone (Expo Go или dev build) в светлой и тёмной теме.
- Документация обновлена, если менялось поведение.

## Чего не делать

- Не отправлять ничего за пользователя (письма, отклики).
- Не парсить массово сайты вакансий; разбираем только страницу, которую дал пользователь.
- Не добавлять аналитику с персональными данными.
- Не менять схему базы без миграции.
